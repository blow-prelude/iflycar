# 固定地面透视变换 C++ 版设计

## 目标

在 `vision_line` 包中新增一个独立的 C++ 相机程序，复现当前 Python
版本的固定地面掩码和鸟瞰透视变换。程序复用已有 `CameraCapture`，所有
运行参数直接写在源码中，不做蓝色地图动态检测，也不保存图片。

## 已确认参数

- 相机索引：`0`
- 相机采集尺寸：`640 x 480`
- 算法处理尺寸：`320 x 240`
- 固定地面起始行：`y = 139`，只保留 `y >= 139`
- 源点顺序：左上、右上、右下、左下
  - `(114, 146)`
  - `(206, 146)`
  - `(271, 184)`
  - `(35, 187)`
- 实际区域宽度：`0.5 m`
- 实际区域长度：`0.75 m`
- 比例：`200 px/m`

## 方案

采用“可测试的算法模块 + 独立相机入口”结构：

- `include/ground_perspective.h`：声明固定掩码、目标点、扩展单应矩阵和
  透视变换接口。
- `src/ground_perspective.cpp`：实现不依赖相机硬件的 OpenCV 算法。
- `src/dynamic_ground_perspective.cpp`：保存固定参数，调用
  `CameraCapture`，运行实时显示循环。
- `test/test_ground_perspective.cpp`：测试固定掩码和透视几何。
- `CMakeLists.txt`：新增算法库、相机可执行目标和条件启用的 gtest 目标。

不把新逻辑放入 `CameraCapture::perspectiveFrame`，避免改变已有寻线程序
使用的旧透视矩阵和固定输出尺寸。

## 数据流

每帧按以下顺序处理：

1. `CameraCapture::captureFrame()` 获取 `640 x 480` 图像。
2. `CameraCapture::correctFrame()` 去畸变，并使用它的返回值。
3. 水平翻转去畸变后的图像。
4. 缩放为 `320 x 240`。
5. 创建固定掩码：`0 <= y < 139` 为 `0`，`139 <= y < 240` 为 `255`。
6. 用掩码清除场外区域。
7. 将四个源点映射到由实际尺寸和像素比例得到的矩形目标点。
8. 将整个固定地面 ROI 的四角经过单应矩阵投影，计算最小包围画布，
   再增加平移矩阵，尽量保留可见地面信息。
9. 使用 `cv::warpPerspective` 生成鸟瞰图。
10. 通过 `cv::imshow` 显示处理图、鸟瞰图和掩码。

按 `q`、`Q` 或 `Esc` 退出，不写入任何图像文件。

## 错误处理

- 相机无法打开时沿用 `CameraCapture` 的异常。
- 空帧打印错误并结束循环，避免把空矩阵传给 OpenCV。
- 非法图像尺寸、实际尺寸或像素比例抛出 `std::invalid_argument`；固定地面
  起始行与 Python 版一致，裁剪到 `[0, 图像高度]`。
- 主函数捕获 `std::exception`，输出原因并返回非零状态。
- 无论正常退出还是异常退出，都关闭相机窗口；相机资源由
  `CameraCapture` 的析构函数释放。

## 构建与依赖

继续使用当前 `find_package(OpenCV REQUIRED)` 的结果，不硬编码 OpenCV
库路径。新增可执行目标链接算法库、`camera_capture` 和 `${OpenCV_LIBS}`。
只有当前 CMake 无法找到 OpenCV 时，才补充用户提供的库路径。

## 测试与验收

C++ 测试不访问相机硬件，至少验证：

- `320 x 240` 掩码的第 `138` 行全黑、第 `139` 行全白。
- 超出图像范围的地面起始行得到定义明确的空或全白掩码。
- 目标矩形为 `100 x 150` 像素。
- 四个标定源点经单应矩阵变换后落在对应目标角点上。
- 扩展画布后的固定地面 ROI 不产生负坐标，输出尺寸为正数。

最终验收包括 C++ 测试、目标编译以及对 CMake 变更的检查。真实相机
画面只由用户在目标设备上进行人工确认。

## 非目标

- 不动态识别蓝色地面边缘。
- 不自动标定四个源点或每米像素数。
- 不修改现有 Python 版本。
- 不修改已有寻线节点的透视行为。
- 不增加命令行参数、ROS 话题或图片保存功能。
