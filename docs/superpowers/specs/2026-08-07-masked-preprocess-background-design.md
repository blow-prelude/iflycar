# 掩膜感知的图像预处理设计

## 目标

修改 `src/vision_line/scripts/image_process.py` 的 `ImageProcess.preprocess`，防止透视变换产生的黑色无效区域参与大尺度背景估计，从而消除有效图像与黑区交界处的白色伪边，同时保留有效区域内部的真实亮线检测能力。

## 范围

- 只修改 Python 版 `image_process.py` 及其 Python 回归测试。
- 保持现有 `preprocess(frame)` 调用兼容。
- 不调整透视矩阵、寻线算法、阈值策略或状态机。
- 不同步修改 C++ 版 `ImageProcess::preprocess`。

## 接口与掩膜语义

`preprocess` 增加可选参数：

```python
preprocess(frame, valid_mask=None)
```

- `valid_mask` 非空时必须与最终被处理图像具有相同的二维尺寸；非零像素表示有效区域。
- 未提供 `valid_mask` 时，从最终被处理的 BGR 图像推导后备掩膜：三个通道全部为零的像素视为无效，其余像素视为有效。
- 图像发生缩放时，显式掩膜使用最近邻插值同步缩放，避免在掩膜边界产生灰度过渡。
- 空掩膜或尺寸不匹配时抛出清晰的 `ValueError`，再由现有异常包装逻辑转换为 `RuntimeError`。

显式掩膜是最可靠的数据来源；自动推导只用于兼容现有调用以及当前“无效区严格填零”的透视输出。

## 背景估计

原算法直接对包含黑区的灰度图做高斯模糊。新算法使用归一化掩膜卷积：

```text
weighted_sum = GaussianBlur(gray * mask)
weight_sum   = GaussianBlur(mask)
background   = weighted_sum / weight_sum
```

只在 `weight_sum` 大于浮点容差的位置执行除法。这样边界附近的背景值只由有效像素贡献，不会被无效黑区拉低。

后续仍使用单向亮特征差值、Otsu 二值化及现有 3×3、三次闭运算。二值化后和闭运算后都重新施加有效掩膜，确保阈值与形态学操作不会把前景扩张到无效区。

## 数据流

1. 按现有优先级取得输入帧。
2. 必要时按现有上限等比例缩放帧，并同步缩放显式掩膜。
3. 取得显式掩膜或从纯黑填充推导后备掩膜。
4. 转灰度并计算掩膜归一化高斯背景。
5. 计算非负亮特征差值并执行 Otsu 二值化。
6. 清零无效区，执行闭运算，再次清零无效区。
7. 返回与现有接口相同的 `uint8` 二值图。

## 测试与验收

新增聚焦的 Python 回归测试，先确认旧实现失败，再实施修改：

1. 构造中央均匀灰色有效区域、两侧黑色无效区；预处理结果在有效区边界附近不得出现白色伪边。
2. 在有效区域内部加入一条明显更亮的线；修复后该亮线仍应被检测为白色。
3. 不传掩膜时，纯黑填充的后备推导得到相同的无伪边结果。
4. 显式掩膜尺寸不匹配时返回清晰错误。
5. 运行新增测试、现有 `vision_line` Python 测试及 Python 语法检查。

## 非目标与已知限制

- 自动推导无法从像素值区分“真实纯黑场景”与“无效纯黑填充”；需要无歧义行为的调用方应传入显式掩膜。
- 本次不改变 `self.frame` 覆盖显式 `frame` 参数的既有优先级，避免夹带无关行为变更。
- 本次不为 C++ 路径实现同类修复。
