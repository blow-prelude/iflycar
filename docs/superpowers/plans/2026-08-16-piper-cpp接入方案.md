# Piper TTS C++ 简化接入方案

## 1. 目标

在现有 `ourgoal` C++ 状态机中直接调用本地 Piper，实现以下三处动态中文播报：

1. 实体车仓储完成：“已将{物品}放入{车间}”；
2. 仿真任务完成：“仿真任务已完成，已将{物品}放入{车间}”；
3. 巡线结束：“任务完成”。

按当前决定，不新增 ROS TTS 节点、不新增 service、不直接链接 Piper 库。C++ 使用
`system()` 调用 Piper；Piper 合成或播放失败时，再用 `system()` 调用现有
`espeak` 降级播报。

本方案已进入实施阶段，当前实现状态和验证结果见第 7 节。

## 3. 设计

### 3.1 调用流程

在 `OURSWITCH` 中增加统一方法：

```cpp
bool speakText(const std::string &text);
```

处理流程：

```text
speakText(text)
  ├─ 读取 Piper 路径、模型路径和临时 WAV 路径
  ├─ 对路径和文本做 shell 单引号转义
  ├─ system(Piper 合成并调用 aplay)
  │    ├─ 返回 0：播报成功，返回 true
  │    └─ 返回非 0：记录 ROS_WARN，进入降级
  └─ system(espeak 播报)
       ├─ 返回 0：记录降级成功，返回 true
       └─ 返回非 0：记录 ROS_ERROR，返回 false
```

业务状态机只调用 `speakText()`，不关心具体命令。播报失败只记录错误，原有状态
流转继续执行，不能因为语音故障卡住比赛流程。

### 3.2 Piper 命令

根据本地旧版 Piper 已确认的参数，命令结构为：

```bash
cd '<piper_runtime_dir>' && \
printf '%s\n' '<text>' | \
./piper \
  --model '<model_path>' \
  --config '<config_path>' \
  --output_file '<wav_path>' && \
test -s '<wav_path>' && \
aplay --quiet '<wav_path>'
```

这条命令一次完成合成和播放。`&&` 保证 Piper 返回非零时不会播放旧的临时 WAV；
`test -s` 拒绝空输出；Piper、WAV 检查或 `aplay` 任一步失败，整个 `system()` 都
返回非零并触发 espeak。

临时输出固定使用 `/tmp/ucar_piper_tts.wav`。当前总任务状态机严格串行，三处播报
不会并发，因此不引入随机文件名、队列或锁。每次 Piper 成功都会覆盖该文件。

### 3.3 espeak 降级命令

降级命令保持与当前工程一致：

```bash
espeak -v zh+f2 -s 130 '<text>'
```

Piper 的合成失败和 `aplay` 播放失败都触发降级。espeak 也失败时只记录错误并返回
`false`；实体仓储流程继续进入后续状态，最终流程继续执行 `ros::shutdown()`。

### 3.4 shell 转义

虽然采用 `system()`，仍不能把物品名、车间名或路径直接拼进命令。新增一个局部
辅助函数 `shellQuote()`：

1. 整个参数用单引号包裹；
2. 参数中的每个单引号 `'` 替换为 shell 安全序列 `'\''`；
3. 文本、工作目录、模型路径、配置路径和 WAV 路径都经过该函数。

这样双引号、分号、反引号、`$()` 和空格只会作为普通文本传给 Piper/espeak，
不会变成额外 shell 命令。

命令中的程序名 `./piper`、`aplay`、`espeak` 和固定选项由代码生成，不接受业务
文本覆盖。

### 3.5 配置

为了保持实现简单，不增加 YAML 和 launch 文件。`speakText()` 每次调用时通过
现有 `nh_.param` 读取以下 ROS 参数，并提供当前本机默认值：

| ROS 参数 | 默认值 |
| --- | --- |
| `piper_runtime_dir` | `/home/ucar/ucar_ws/3rdparty/piper` |
| `piper_model_path` | `/home/ucar/ucar_ws/3rdparty/piper/models/zh_CN-huayan-medium.onnx` |
| `piper_config_path` | `/home/ucar/ucar_ws/3rdparty/piper/models/zh_CN-huayan-medium.onnx.json` |
| `piper_wav_path` | `/tmp/ucar_piper_tts.wav` |

默认情况下无需增加启动参数。部署位置改变时，可在 launch 或命令行设置这些参数，
不需要重新编译。

### 3.6 返回值与日志

只按 `system()` 是否返回 0 判断成功：

- Piper 成功：`ROS_INFO("Piper speech completed")`；
- Piper 失败：打印返回值和“fallback to espeak”；
- espeak 成功：打印 `ROS_WARN`，明确本次使用了降级；
- 两者都失败：打印 `ROS_ERROR`，包含两次返回值。

日志中可打印播报文本，但不打印完整 shell 命令，避免日志过长，也避免未来路径中
可能出现的敏感信息被原样输出。

4. 物品名和车间名中的 shell 特殊字符不会被执行为命令。
5. 不新增 ROS 节点、service、action、消息类型或第三方编译依赖。
6. Piper 部署路径可以通过 ROS 参数覆盖。
7. 仓库内 Piper 运行时不依赖 `/home/ucar/piper_tts/` 外部目录，`ldd` 无
   `not found`。
8. `catkin_make --pkg ourgoal` 构建成功。
9. 除三处播报调用、辅助函数和 CMake 源文件列表外，没有其他业务行为变化。
