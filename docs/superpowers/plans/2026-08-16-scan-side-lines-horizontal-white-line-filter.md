# `scan_side_lines` 横向白线误检优化设计

## 目标

优化 `src/vision_line/src/image_process.cpp` 中的
`ImageProcess::scan_side_lines`：当蓝色赛道上的水平或近水平白线覆盖边线搜索起点时，
不再把白线端点错误地加入左右边线。

本方案同时作用于 `get_side_line_task_1` 和 `get_side_line_task_2`，并尽量保留画面中
可能接近水平的真实赛道边界。

## 问题分析

`scan_side_lines` 从图像下方向上逐行扫描，每侧从预计位于赛道内部的搜索起点向外寻找
第一个黑白跳变点。现有稳定点和连续性检查只能判断连续多行中的候选点是否相邻，无法
判断这些点属于赛道边界还是横向白线的端点。

在 `captured_image_20260816_040157.jpg` 中，横向白线落在 task1 的扫描区间内，并覆盖
赛道内部。扫描起点落在白线上时，继续向外搜索会先找到横线端点；端点在相邻多行中可能
保持连续，因此存在被确认为边线的风险。

不采用统一角度过滤，因为急弯中的真实赛道边界在画面中也可能接近水平。也不在本次方案中
引入 Hough 变换或删除横向连通域，避免增加计算和误删与横线相连的真实边界。

## 设计方案

保留现有逐行构造 `row_mask`、`row_diff` 以及左右候选跳变点的搜索逻辑，只在每侧开始
搜索前检查该侧靠近赛道内部的搜索起点像素。

### 正常行

当搜索起点为黑色时，认为起点仍处于没有白色标线覆盖的赛道内部，完全沿用现有流程：

1. 在当前动态搜索区间内寻找第一个跳变点；
2. 调用 `add_point_with_stable_start` 做初始稳定和连续性判断；
3. 成功添加后更新 `prev_row_left_x` 或 `prev_row_right_x`；
4. 按现有规则更新 miss 计数、拐点状态和左右边线最小距离检查。

### 横线遮挡行

当某侧搜索起点为白色时，将该侧当前行判定为横线遮挡：

- 不在该侧搜索跳变点；
- 不向边线添加候选点；
- 不更新对应的 `prev_row_*_x`；
- 不增加、清零或重置已有 miss 计数；
- 已经稳定的边线保留稳定状态和原搜索锚点；
- 尚未稳定的边线清空对应稳定点缓冲，避免遮挡前后的横线端点共同凑满
  `init_stable_count`。

横线经过后，搜索起点重新变黑，扫描从遮挡前保留的锚点继续。边线中缺少的少量行由现有
插值流程补齐。

左右两侧独立判断遮挡；一侧起点为白色不会阻止另一侧在同一行正常搜索。

## 保持不变的行为

- `row_mask` 和 `row_diff` 的生成方式不变；
- 左右跳变点的查找方式不变；
- 动态搜索范围、稳定点数量、连续性阈值和 miss 阈值不变；
- 左右边线最小距离和拐点检测逻辑不变；
- 插值、边界填充、中线计算和多项式拟合逻辑不变；
- 停止线检测继续使用原始二值图，不受边线遮挡判断影响；
- 不新增 `ImageProcessConfig` 参数或公开 API；
- 不同步旧 Python 对照实现。

## 测试与验收

### 自动测试

1. 在正常双边线中加入覆盖内部搜索起点、但两端仍存在跳变的横向白条，验证拟合中线
   不向横线端点偏移。
2. 横线出现在初始未稳定阶段时，验证稳定点缓冲被清空，横线端点不能形成边线。
3. 横线出现在稳定跟踪阶段时，验证稳定状态和搜索锚点得以保留，横线之后可以续接原边线。
4. 验证普通丢线仍按原 `miss_threshold` 累计和重置，只有搜索起点为白色的遮挡行不计 miss。
5. 验证 task1、task2、`BOTH`、`LEFT_ONLY` 和 `RIGHT_ONLY` 模式下正常竖直或斜向边线
   的结果不变。

### 实拍验收

使用 `src/vision_line/pictures/captured_image_20260816_040157.jpg` 及实际视频检查：

- 横线所在行允许出现短暂边线空洞，但不能锁定横线端点；
- 横线之后应继续跟踪原赛道边界；
- 拟合中线和目标点不应因横线端点产生明显横向跳变；
- 停止线检测结果保持正常；
- 在 RK3588/ARM ROS 环境完成 `vision_line` 构建和运行验证。

## 前提与边界

- `preprocess` 输出中，`0` 表示没有白色特征覆盖的赛道区域，非零表示白色特征；
- 需要过滤的水平或近水平白线主要横穿赛道，并会覆盖至少一侧的内部搜索起点；
- 完全位于单侧且没有覆盖搜索起点的孤立白线仍由现有连续性规则处理；
- 本设计不按角度统一删除候选点，以避免误删真实急弯边界。
